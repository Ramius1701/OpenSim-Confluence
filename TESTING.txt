= Testing OpenSim-Confluence =

== Building ==

This project builds with the .NET SDK, not NAnt. On Windows, run
runprebuild.bat then compile.bat (generated by runprebuild.bat). On
Linux, run ./runprebuild.sh then ./compile.sh. Both ultimately invoke:

    dotnet build -c Release OpenSim.sln

Mac has not been verified.

== Unit Tests: known limitation ==

Unit test source exists in the tree (NUnit-based, under Tests/
subdirectories throughout OpenSim/) and prebuild.xml defines real
<Project> stanzas for 20 of them (OpenSim.Framework.Tests,
OpenSim.Region.CoreModules.Tests, OpenSim.Data.Tests, and others).

As of 2026-08-18, running runprebuild does not generate project files
for any of them - confirmed by running it and diffing the "Creating
project:" output against every Test project defined in prebuild.xml.
This is not something this repository broke; it reproduces with
upstream opensim/opensim's own prebuild.xml too, which uses the same
pattern (several Test projects share the same `path` as their non-test
counterpart, relying on file-match rules alone to separate them - a
pattern this particular prebuild.dll build does not appear to handle).

Practical effect: nobody who runs runprebuild.bat/.sh on this codebase
today gets any test project added to their solution, and there is
currently no verified way to build or run these tests through the
documented process. See prebuild.xml's own top-of-file comment and
PROJECT_LOG.md for the full investigation. Fixing this for real (either
finding a working prebuild.dll build or restructuring the affected Test
project paths) is left as its own effort, not attempted here.
